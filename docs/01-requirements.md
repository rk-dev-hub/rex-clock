# 要件定義書

## 1. 目的・背景

従業員の出退勤・休憩を記録し、労働基準法に準拠した労働時間・割増賃金の
基礎データを月次で集計する。誤打刻や休暇は申請・承認のワークフローで統制する。

## 2. 登場人物（ロール）

| ロール   | 説明                         | 主な権限                                                                                                          |
| -------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| EMPLOYEE | 一般従業員                   | 自分の打刻・打刻修正申請・休暇申請・自分の勤務表閲覧                                                              |
| ADMIN    | 管理者（人事・経営者を想定） | 全員の勤怠閲覧、申請の承認/却下、ユーザー発行・無効化、就業規則マスタ・休日カレンダー管理、月次締め、CSV/PDF 出力 |

- ADMIN も打刻機能を利用できる（ADMIN は EMPLOYEE の全機能を包含）。
- 承認は「自分以外の申請」に対してのみ可能（自己承認禁止）。

## 3. 機能要件

### 3.1 認証・アカウント

- FR-A1 ADMIN がユーザーを作成する（氏名、メール、社員番号、入社日、雇用区分、所定勤務パターン、ロール、初期パスワード）。
- FR-A2 ユーザーはメール＋パスワードでログインする。セルフサインアップは不可。
- FR-A3 初回ログイン時にパスワード変更を必須にする。
- FR-A4 ユーザーは自分のパスワードを変更できる。ADMIN は任意ユーザーのパスワードをリセットできる。
- FR-A5 ADMIN はユーザーを「無効化」できる（退職者想定）。無効ユーザーはログイン不可だが過去データは保持。
- FR-A6 セッションは一定時間で失効する。ログアウトを提供する。

### 3.2 打刻（タイムクロック）

- FR-C1 出勤・退勤・休憩開始・休憩終了を打刻する。打刻時刻はサーバ時刻を秒精度で保存し、集計は分単位。
- FR-C2 当日の打刻状態（未出勤／勤務中／休憩中／退勤済）に応じて押下可能なボタンのみ表示する。
- FR-C3 打刻は「打刻イベント（追記のみ・不変）」として記録し、そこから日次の勤怠サマリを導出する。
- FR-C4 二重出勤、休憩と勤務の矛盾（退勤後の休憩開始等）を拒否する。日跨ぎ勤務（退勤が翌日）に対応する。
- FR-C5 打刻漏れ・誤打刻は「打刻修正申請」で是正する。従業員は直接編集できない。
- FR-C6 ADMIN は代理打刻（対象ユーザー・種別・時刻・理由）を登録できる。監査ログに操作者を残す。

### 3.3 打刻修正申請

- FR-M1 従業員は対象日について、打刻イベントの追加・時刻変更・削除を申請できる（複数明細＋理由必須）。
- FR-M2 申請は 下書き → 申請中 → 承認 / 却下 の状態を持つ。申請中は取消可能。
- FR-M3 ADMIN が承認すると申請内容が実データに反映され、日次サマリと月次集計が再計算される。
- FR-M4 却下時はコメント必須。申請者に結果が表示される。
- FR-M5 締め済みの月に対する修正申請は、ADMIN が「再オープン」しない限り不可。

### 3.4 休暇申請

- FR-L1 休暇種別: 有給休暇（全日／午前半休／午後半休）、欠勤、特別休暇（無給）。有給を主対象とする。
- FR-L2 従業員は期間（開始日〜終了日）または単日、種別、半休区分、理由を指定して申請する。
- FR-L3 申請時に有給残日数を検証し、残不足なら警告（却下はしないが ADMIN に表示）。
- FR-L4 状態は 申請中 → 承認 / 却下。承認済の取消は「取消申請」で行う。
- FR-L5 承認済の有給は残日数を消化し、日次サマリに休暇として反映（全日=所定労働、半休=所定の1/2 を労働扱い相当としてカウント）。
- FR-L6 ADMIN は有給の付与（日数・付与日・失効日・理由）を登録でき、付与／消化の履歴を残す。
- FR-L7 有給の消化順は付与日が古いもの（＝失効が近いもの）から。

### 3.5 承認（ワークフロー）

- FR-W1 ADMIN 向けに「承認待ち一覧」（打刻修正・休暇・取消）を表示する。
- FR-W2 一括ではなく1件ずつ内容を確認して承認/却下する。差分（変更前→変更後）を表示する。
- FR-W3 承認・却下は監査ログに記録（誰が・いつ・対象・コメント）。

### 3.6 勤怠一覧・日次サマリ

- FR-V1 従業員は自分の月次カレンダー/リストで、日ごとの出退勤・休憩・実働・残業・遅刻早退・休暇・申請状態を確認する。
- FR-V2 異常（打刻漏れ、休憩不足、法定休日労働、所定超過など）をアイコン/色で強調する。
- FR-V3 ADMIN は対象ユーザーを切り替えて同じ画面を閲覧できる。

### 3.7 月次集計・勤務表・出力

- FR-R1 締め日（設定値）で区切った月次期間について、ユーザー別に以下を集計する:
  出勤日数、欠勤日数、有給取得（日/半日）、総労働時間、所定内労働、法定内残業、法定外残業（25%）、
  月60時間超残業（50%）、深夜労働（25%）、法定休日労働（35%）、遅刻回数・時間、早退回数・時間、休憩合計。
- FR-R2 集計結果を月次勤務表として画面表示する（日別明細＋月合計）。
- FR-R3 汎用 CSV を出力する（日別明細版・月次サマリ版の2種）。文字コード・区切りは設定（既定 UTF-8 BOM, カンマ）。
- FR-R4 印刷用 PDF（月次勤務表 A4）を出力する。
- FR-R5 ADMIN は月次を「締め」できる。締め後は当該期間の打刻・申請反映がロックされる。「再オープン」も可能で監査ログに残る。

### 3.8 マスタ管理（ADMIN）

- FR-S1 就業規則設定（組織単位・単一）: 所定労働時間/日、所定始業・終業、休憩の基準（実打刻を採用／所定休憩の自動控除、控除ルール）、締め日、
  時間外割増率、深夜割増率、法定休日割増率、月60h超割増率、深夜時間帯（既定 22:00–翌5:00）、週の起算曜日、端数処理（分単位の丸め＝既定なし）。
- FR-S2 勤務パターン（所定始業・終業・休憩時間・所定労働時間・適用曜日）を定義し、ユーザーに割り当てる。「標準パターン」1件のみでの運用も可。
- FR-S3 休日カレンダー: 内蔵祝日データの取込、法定休日の曜日設定（既定 日曜）、所定休日（既定 土曜）、会社独自の休業日・営業日（振替）の登録。
- FR-S4 祝日データ更新スクリプトを同梱（内閣府 CSV を元に seed 用 JSON を再生成）。ネットワークなしでも初期データで動作する。

### 3.9 監査ログ

- FR-AU1 打刻の作成/修正/削除、承認/却下、締め/再オープン、ユーザー発行/無効化、マスタ変更を記録する。
- FR-AU2 記録項目: 日時、操作者、対象、種別、変更前後（差分）、理由/コメント。ADMIN が閲覧できる。

## 4. 非機能要件

| 分類           | 要件                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対応言語       | 日本語のみ（i18n 前提の文言分離まではしない）                                                                                                            |
| タイムゾーン   | Asia/Tokyo 固定。DB は UTC 保存、表示・集計で JST 変換                                                                                                   |
| ブラウザ       | 最新の Chrome / Firefox / Safari / Edge。PC 主体、スマホ幅でも打刻できるレスポンシブ                                                                     |
| 認可           | 全 Server Action / Route Handler でロールと本人確認を強制。EMPLOYEE は他人のデータに一切アクセス不可                                                     |
| パスワード     | bcrypt (cost 12 以上)。平文・可逆保存しない。最低8文字の検証                                                                                             |
| 監査           | 3.9 の操作は追記のみのログに残す。打刻イベントは物理削除せず「取消」フラグで扱う                                                                         |
| データ整合     | 月次集計は打刻・申請・マスタから決定的に再計算可能（キャッシュしても再現できる）                                                                         |
| セキュリティ   | CSRF 対策（Server Actions の origin 検証）、XSS 対策（React 標準＋出力エスケープ）、SQL は Prisma 経由のみ、機密値は環境変数                             |
| 機密情報の管理 | `.env` は Git 管理外。`.env.example` はダミー値。seed の従業員データは架空。README にセットアップ手順                                                    |
| 差し替え性     | DB は `DATABASE_URL` の変更のみで PostgreSQL 互換に移行可能。Prisma provider 変更で他 RDBMS も視野（未検証と明記）                                       |
| テスト         | 集計ロジックは純粋関数＋網羅的な単体テスト。主要フローは E2E                                                                                             |
| パフォーマンス | 想定 〜100 ユーザー・数年分。月次集計は対象ユーザー×期間で数百件程度、同期処理で許容                                                                     |
| 可用性・運用   | デプロイ構成は導入先の環境に合わせて設定する（リポジトリには含めない）。ローカル起動手順・Docker Compose・マイグレーション手順・本番環境の設定手順を提供 |

## 5. 主要ユースケースフロー

### UC-1 通常の1日

1. 従業員がログイン → ダッシュボードで「出勤」打刻。
2. 昼に「休憩開始」→「休憩終了」。
3. 退勤時に「退勤」打刻 → 当日サマリ（実働・残業）が表示。

### UC-2 打刻漏れの是正

1. 従業員が勤怠一覧で前日の退勤漏れに気づく。
2. 「打刻修正申請」で退勤 19:30 を追加、理由を記入し申請。
3. ADMIN が承認待ち一覧で差分を確認 → 承認。
4. 当該日と月次集計が再計算される。監査ログに記録。

### UC-3 有給取得

1. 従業員が「休暇申請」で来週月曜を有給（全日）で申請。
2. システムが残日数を検証（残 12 日 → OK）。
3. ADMIN が承認 → 残 11 日、当日は所定労働時間ぶんを労働扱いとして集計。

### UC-4 月次締めと出力

1. 締め日翌日、ADMIN が対象期間の未処理申請を確認・処理。
2. 「締め」を実行 → 期間ロック。
3. 月次勤務表を画面確認し、CSV（日別・サマリ）と PDF を出力。
4. 修正が必要になれば「再オープン」→ 修正 → 再締め（監査ログに全操作）。

## 6. バリデーション・エラー方針（抜粋）

- 打刻: 状態機械に反する打刻は 409 相当で拒否し、理由を表示。
- 休暇: 過去日申請は警告（ADMIN 承認で可）。重複期間の申請は不可。
- 申請: 理由未入力は不可。却下はコメント必須。
- 締め済み期間への変更は一律ブロックし、再オープン導線を案内。

## 7. スコープ外（将来拡張）

- フレックス・裁量労働・変形労働時間制、シフト管理
- マルチテナント（複数企業・部署階層）
- 工数／プロジェクト別集計、給与ソフト連携フォーマット
- 時間単位有給、モバイルアプリ、打刻の位置情報・IC カード
- 有給の自動付与（勤続年数テーブル）※ 現行は管理者による手動付与＋付与履歴のみ
